Automação de Cadastro de Usuários

Automação desenvolvida em Python e Playwright para realizar o cadastro de aproximadamente 140 usuários no TOTVS Protheus, atendendo à integração operacional de seis novas unidades.

  • Python
  • Playwright
  • CSV
  • TOTVS Protheus WebApp

Visão geral

Durante um processo de integração de seis novas unidades, surgiu a necessidade de cadastrar aproximadamente 140 usuários no ERP TOTVS Protheus dentro de um prazo reduzido.

Para atender à demanda, foi desenvolvida uma automação utilizando Python e Playwright, executando as operações de cadastro por meio da interface do Protheus WebApp.

A abordagem permitiu utilizar funcionalidades já disponíveis no ERP e reduzir a necessidade de execução repetitiva das operações de cadastro.

O desafio

O volume de usuários e o prazo disponível tornavam o cadastramento manual uma atividade operacionalmente onerosa.

Além disso, a interface do Protheus WebApp apresentava comportamentos específicos, incluindo elementos dinâmicos, campos que exigiam interações particulares e janelas cuja exibição dependia da sequência correta de ações.

A automação também precisava utilizar informações provenientes de um arquivo CSV preparado por terceiros, tornando a qualidade dos dados de entrada uma dependência importante.

A solução técnica

Foi desenvolvida uma automação em Python utilizando Playwright para interagir com a interface do TOTVS Protheus WebApp.

A solução utilizava um arquivo CSV como fonte dos registros e executava as operações de cadastro por meio das funcionalidades existentes no ERP, incluindo a utilização de usuários-modelo como referência para os novos cadastros.

Durante o desenvolvimento, foi necessário tratar particularidades da interface, como elementos ocultos no DOM, campos que exigiam duplo clique e janelas dependentes de interações específicas.

A abordagem escolhida priorizou a viabilidade de implementação dentro do prazo disponível.

Decisão técnica — Automação de interface

A decisão considerou o prazo disponível e os requisitos da demanda.

  • Abordagem utilizada: Python + Playwright

    Permitiu automatizar o cadastro utilizando o fluxo já existente no sistema, sem depender da implementação prévia de uma nova integração.

  • Alternativa considerada: integração via API

    Uma integração por API poderia oferecer maior robustez para uma solução permanente, mas exigiria desenvolvimento e validações adicionais.

Minha atuação no projeto

Atuei na análise técnica, definição da abordagem e desenvolvimento da automação em Python e Playwright.

Minha responsabilidade envolveu compreender o fluxo de cadastro no TOTVS Protheus, identificar os elementos necessários à interação automatizada, tratar comportamentos específicos do WebApp e estruturar a leitura dos dados de entrada.

Durante a execução, também foram necessários ajustes operacionais para lidar com inconsistências nos registros recebidos, permitindo concluir o cadastramento dos usuários previstos.

A iniciativa demonstrou minha capacidade de utilizar programação para solucionar uma demanda empresarial crítica, equilibrando prazo, complexidade técnica e necessidades operacionais.

Resultados e aprendizados

A automação permitiu concluir o cadastramento de aproximadamente 140 usuários no TOTVS Protheus, atendendo à necessidade operacional de integração de seis novas unidades.

Um dos principais desafios encontrados durante a execução foi a qualidade dos dados de entrada.

O arquivo CSV, preparado por terceiros com base nas informações cadastrais previamente fornecidas, apresentou situações de duplicidade que exigiram intervenção manual.

Quando uma duplicidade era identificada, o processamento precisava ser interrompido para correção do arquivo e remoção dos registros já processados, permitindo reiniciar a automação sem repetir os cadastros concluídos.

Apesar dessas limitações, todos os usuários previstos foram cadastrados.

Oportunidades de evolução

A experiência evidenciou oportunidades de evolução, especialmente na validação preventiva dos dados, identificação de registros duplicados, controle de progresso e retomada segura após interrupções.

Essas melhorias são oportunidades identificadas, não funcionalidades já implementadas.

O tratamento das duplicidades e a retomada eram manuais.
