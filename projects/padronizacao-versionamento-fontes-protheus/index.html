Git & Governança

Padronização do Versionamento de Fontes Protheus

Implantação de práticas de controle de versão com Git e GitHub para organizar fontes ADVPL/TLPP, padronizar o desenvolvimento e aumentar a rastreabilidade das alterações.

  • Git
  • GitHub
  • ADVPL/TLPP
  • Governança

Visão geral

Projeto de implantação e padronização do controle de versão dos arquivos-fonte ADVPL/TLPP do ERP TOTVS Protheus, utilizando Git e GitHub como ferramentas de organização e rastreabilidade do desenvolvimento.

A iniciativa buscou evoluir o gerenciamento dos fontes, substituindo a dependência de diretórios e cópias manuais por um repositório versionado, com histórico de alterações e práticas documentadas para utilização.

O desafio

O ambiente de desenvolvimento possuía um histórico de customizações e arquivos organizados em diretórios, com separação entre fontes preparados para compilação e arquivos em desenvolvimento.

Esse modelo dificultava a rastreabilidade das alterações, a identificação de versões e a organização de atividades simultâneas.

Era necessário estabelecer uma estrutura que permitisse centralizar os arquivos-fonte, preservar o histórico de alterações e definir procedimentos consistentes para o trabalho técnico.

A solução técnica

Foi implantado um repositório Git/GitHub para gerenciamento dos fontes Protheus, aproveitando o levantamento e a organização realizados anteriormente no projeto de inventário do RPO.

  • Estruturação do repositório de código-fonte.
  • Carga inicial dos arquivos ADVPL/TLPP.
  • Organização dos arquivos classificados e pendentes de classificação.
  • Definição de convenções de nomenclatura para branches.
  • Padronização de mensagens de commit.
  • Documentação de procedimentos para utilização do Git/GitHub.
  • Utilização prática de branches, commits, sincronização e integração de alterações.

Foram preparados materiais de orientação, incluindo documentação CONTRIBUTING.md e instruções operacionais para utilização do fluxo.

O controle de versão passou a ser utilizado em atividades reais de desenvolvimento e manutenção do Protheus.

Minha atuação no projeto

Atuei na análise da estrutura existente, planejamento e implantação do processo de controle de versão dos fontes Protheus.

Minha participação envolveu a organização inicial do repositório, configuração do ambiente Git/GitHub, estabelecimento de convenções de utilização e preparação de documentação técnica para orientar o trabalho.

Também utilizei o fluxo de versionamento durante atividades reais de desenvolvimento, realizando operações de criação e atualização de branches, commits, sincronização com o repositório remoto e integração de alterações.

A iniciativa demonstrou minha atuação na melhoria de processos técnicos, organização de ativos de software e adoção de práticas de governança do desenvolvimento.

Fluxograma funcional

Processo de trabalho com Git/GitHub, do inventário dos fontes ao histórico e à rastreabilidade.

  1. Inventário e organização dos fontes
  2. Estruturação do repositório Git/GitHub
  3. Carga inicial dos arquivos
  4. Criação de branch por atividade
  5. Desenvolvimento e registro de commits
  6. Sincronização com o GitHub
  7. Integração das alterações ao repositório principal
  8. Histórico e rastreabilidade do desenvolvimento

Resultados alcançados

O projeto resultou na implantação de um repositório versionado para os fontes ADVPL/TLPP, com organização estruturada e histórico de alterações.

Foram estabelecidas práticas documentadas para utilização do Git/GitHub, incluindo convenções de commits e procedimentos para trabalho com branches.

O versionamento foi utilizado em atividades reais de desenvolvimento e manutenção do ERP, com registros de commits, sincronização com o repositório remoto e integração de alterações.

A iniciativa ampliou as condições de rastreabilidade, organização e controle do código-fonte, estabelecendo uma base técnica para a evolução das práticas de governança.

  • Repositório implantado

  • Fluxo de versionamento utilizado

  • Práticas documentadas

Limitações e oportunidades de evolução

Embora o repositório e as práticas de versionamento tenham sido implantados, não há confirmação de adoção integral do fluxo padronizado por todos os profissionais da equipe.

A ampliação da adoção, o aperfeiçoamento das revisões de código e a formalização de critérios de aprovação representam oportunidades de evolução.

A apresentação corporativa preparada para o projeto não foi publicada.
